# Nod by n8n

## 事件背景

Product Hunt 官方 API 将 post 1311491 标为“Nod by n8n”，Maker 列表含 Johan Cutych 等四人；本批冻结为 daily #1、235 votes、32 comments。它由 n8n Labs 以研究预览发布，试图把只给建议的聊天助手变成能在应用和真实网站完成任务的个人代理，并与 n8n 主产品保持独立。

## 核心观点 / 产品机制

Nod 在用户的 Mac、Windows PC 或自托管服务器上运行：一个 Node 进程协调数据库、模型与策略，命令和浏览器分别进入隔离容器，构成所谓“私有计算机”。服务器保管密钥，供应商只获得任务所需内容；托管应用连接仍可能经过 n8n 默认连接服务及 Composio。用户可选 OpenAI、Anthropic、Gemini、OpenRouter 等，也可接 Ollama 等兼容服务器。服务器以用户原话、规则和动作参数做信任检查；网页、邮件不能授予权限，未被请求的发送、预订、发布、删除会暂停确认，付款一律审批。但检查器本身仍是模型，官方承认会误判。仓库归属 n8n-io，根许可证为 Apache-2.0。

## 社区热议与争议点

官方 GraphQL 两页取得19条顶层评论、13条回复，均无下一页；除 Maker 列表外用户身份被脱敏。四个代表例子是：Maker Johan 把私有虚拟机和动作闸门作为核心卖点，属于发布方口径；一名隐私软件从业者追问令牌位置，身份脱敏的产品方回复承认是混合模式——Gmail、Slack 令牌由 Composio 持有，部分令牌才留在本机；另一用户追问审批与审计，回复称读取、搜索可继续，超出原请求的发送、预订、付款、删除才停下；还有用户质疑自主任务的可靠性和错误恢复，发布时未获回答。

## 行业影响与未来展望

Nod 把开源、可选模型和服务器侧权限闸门组合起来，代表个人代理从“会聊”转向“能执行、可追责”。不过“本地”不等于零外传：使用统计默认开启，模型与连接服务仍构成数据边界。它目前只支持单一所有者，本机休眠即停，也无合规认证；后续托管、多人协作若落地，权限隔离、恢复语义和独立安全验证更关键。
