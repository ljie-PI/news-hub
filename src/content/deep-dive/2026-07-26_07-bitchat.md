# permissionlesstech/bitchat

## 1. 定位与痛点剖析
bitchat 是一款去中心化的点对点即时通讯 App，主打「无账号、无手机号、无中心服务器」。它解决的核心痛点是：在网络中断、被封锁或完全离线的场景下（抗议、灾害、偏远地区），人们依然需要安全通信。传统 IM 依赖运营商与云端服务器，一旦断网或被审查即失效。bitchat 用蓝牙 Mesh 提供离线通信能力，并以类 IRC 的命令交互（`/msg`、`/who`、`/slap`）唤起老网民的亲切感，被作者称为「side-groupchat」。

## 2. 核心架构与技术细节
bitchat 采用双传输层的混合架构。离线侧是基于蓝牙 LE 的 Mesh 网络：设备自动发现彼此，消息通过邻近设备多跳中继（最多 7 跳），使用为蓝牙约束优化的紧凑二进制协议，并借助 Noise Protocol 实现带前向保密的端到端加密，配合自适应功耗占空比省电。在线侧接入 Nostr 协议，通过号称 290+ 的全球中继网络（自报口径）实现跨国触达，用 geohash 坐标划分「街区/社区/城市/国家」等地理频道，私信采用 NIP-17 gift-wrap 加密并使用每区域临时密钥。私信路由具备智能传输选择：优先蓝牙，其次 Nostr 回退，均不可用时智能排队待送达。此外还支持 LZ4 压缩、三击紧急擦除。

## 3. 竞品对比与生态站位
相较 Signal、Telegram 等依赖服务器的加密 IM，bitchat 的差异化在于「离线可用」与「零身份标识」。与同类蓝牙 Mesh 方案 Bridgefy、FireChat 相比，它叠加了 Nostr 这一开放去中心化协议，兼顾本地与全球两种触达路径，站位更接近「抗审查的公共通信基础设施」。项目采用公共领域（public domain）授权，几乎无使用门槛。

## 4. 开发者反馈与局限性
项目已上架 App Store（bitchat-mesh），支持 iOS 与 macOS 原生，⭐约 28662（自报口径）。局限性也明显：蓝牙 Mesh 受限于物理距离与设备密度，跳数上限 7 跳意味着覆盖范围有限；离线通信在人烟稀少处几乎不可用。构建流程依赖 Xcode 与开发者 Team ID 手动配置 entitlements，上手成本偏高。Nostr 中继的可用性与抗审查性也取决于第三方网络。
