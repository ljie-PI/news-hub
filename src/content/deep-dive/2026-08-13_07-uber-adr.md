# uber/ADR

## 定位与痛点剖析

ADR 是面向企业 AI 代理的观测、基准与威胁检测系统。传统端点安全能看见进程，却难还原 Claude Code、Cursor 或 Codex 的意图、对话和工具调用链；ADR 将这些轨迹标准化，让安全团队能审计代理为何访问文件、调用 MCP 服务或传出数据。

## 核心架构与技术细节

Sensor 用各平台解析器读取 JSONL 或 SQLite 日志，统一为含会话、消息、工具与环境上下文的 AgentEvent，再导出给检测管线或 SIEM。Detection 采用两级策略：先高召回分流，再让推理代理结合源码、威胁情报和策略深查可疑会话。仓库还提供 ADR-Bench 与 AgentDojo 接入；README 所列三百余任务、一百三十三个 MCP 服务及论文指标均为项目方自报，应通过复现实验核验。

## 竞品对比与生态站位

LlamaFirewall 等运行时护栏更轻，适合请求级阻断；AgentDojo 侧重评测。ADR 把跨工具遥测、基准和调查式检测串成闭环，企业上下文更强，但运行完整双代理检测需要模型密钥与 Claude CLI，成本和部署复杂度更高。它更像代理安全领域的检测响应层，而非单一提示过滤器。

## 开发者反馈与局限性

仓库明确声明 Detection 是隔离环境使用的研究制品，锁定依赖含已知漏洞，不应连接真实凭据或生产 MCP。预防模块与离线红队 Explorer 尚未开源。真实 issue #42 还指出分流阶段缺少对不可见 Unicode 与双向文本控制符的确定性扫描，可能过度依赖模型判断；近期解析器 issue 也显示上游工具日志格式变化会持续带来兼容维护。
