# OpenCode 2.0

## 事件背景
OpenCode 2.0 以开源、模型无关的编码代理身份登上 Product Hunt 日榜第 2；本批冻结为 236 votes、11 comments。它并非界面换皮，而是把终端工具重构为可由多种客户端与脚本共用的代理运行平台。

## 核心观点 / 产品机制
2.0 让单一后台服务自动常驻，TUI、Web、桌面端及 `@opencode/client` 脚本共享会话与执行状态；后者还能自动发现本地服务。Code Mode 以受限 JavaScript 把 MCP 和 OpenAPI 工具转成函数，使筛选、映射、多工具调用在一次往返内完成，减少上下文膨胀。子代理与 shell 命令可转入后台，完成后通知主会话。代价是三类明确断点：V1 插件须重写，旧 server API/客户端须迁移，分层 `tui.json(c)` 改为全局 `cli.json`。

## 社区热议与争议点
官方 GraphQL 按 post 1278232 取得 11 条顶层评论及 4 条回复。Johannes N 称团队已使用数月且满意；Chrissy Lim 认可多模型选择，同时追问任务中途换模型能否保持会话；另一用户询问自定义 LLM endpoint；还有评论者直指上下文墙，担心临近收尾的有损摘要破坏任务。仓库问题进一步压低乐观预期：#55253 显示迁移后旧会话仍在库中却因归入 `global` 而不可见；#55250 复现断线重连后误报目录失效；#55228 证实子代理未继承父会话环境变量。

## 行业影响与未来展望
这次升级把竞争焦点从“选哪款模型”推向代理底座：共享服务、可编排工具和异步执行更适合长期任务及团队自动化。但发布说明未给性能基准，且迁移、重连、环境继承均已有可复现回归；团队应先备份配置，在低风险项目逐项验证插件、会话和后台任务，再扩大部署。
