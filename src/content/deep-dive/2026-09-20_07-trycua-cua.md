# trycua/cua

## 定位与痛点剖析

Cua 是面向计算机使用智能体的开源基础设施，而非单一模型。它整合桌面驱动、隔离沙箱、云端机群与评测，服务跨应用智能体和批量实验。痛点在于模型会看图，不代表系统能稳定操作窗口、保持状态、隔离风险并复现实验。本批次单日新增一千一百二十四颗星。

## 核心架构与技术细节

单仓包含三条链路：Cua Driver 通过命令行、模型上下文协议或类型化软件包操控桌面；Sandbox 统一管理本地容器、虚拟机及云端桌面；Cua-Bench 把任务、初态、适配器和评估器封装为可复现实验。Driver 以 Rust 实现守护进程和平台后端，Python、TypeScript 绑定由 UniFFI 生成，并置于带版本的稳定 C 接口之上。Lume 负责苹果芯片虚拟化。官方矩阵明确：视窗系统仅“有限支持”，被遮挡界面的原始后台输入通常不可行。

## 竞品对比与生态站位

Stagehand 与 Playwright MCP 更专注浏览器；E2B Desktop 提供隔离的 Linux 图形沙箱。Cua 同时覆盖原生桌面、浏览器、三大桌面系统和本地或云端环境，并打通驱动、环境与评测。代价是单仓边界宽、权限和平台差异更复杂；它更像智能体的执行与实验底座，而非网页自动化库。

## 开发者反馈与局限性

开放问题提供了具体边界。问题四千零一报告：Windows 上的零点二十二版 Driver 未实现协议心跳，使用心跳健康检查的客户端约每五十五秒重启一次；报告给出的临时办法是关闭心跳，尚不能证明新版已修复。问题三千九百八十则报告零点二十八点二版在新版苹果系统重复启动应用时可能选中无标题窄窗口，导致状态树为空；可暂按标题重新选窗。这些是单个可复现报告，不应外推为所有平台普遍失效，但说明跨协议、跨系统一致性仍在打磨。
