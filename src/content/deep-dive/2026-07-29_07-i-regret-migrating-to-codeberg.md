# I regret migrating to Codeberg

## 1. 事件背景
作者曾将项目从主流平台迁移到非营利、社区驱动的自托管 Git 平台 Codeberg，如今却公开表达后悔。文章聚焦 Codeberg 近期强硬的政策取向——尤其是禁止 AI 生成代码、要求移除相关署名——引发对这类小众 FOSS 平台治理边界的广泛讨论。帖子在 HN 获 557 分、564 条评论。

## 2. 核心观点
作者认为 Codeberg 不应以"立场"限制平台上可托管的项目类型，作为托管他人源码的服务，其政策应更中立包容；而对资源做适度限制尚可接受。批评核心在于平台把价值判断强加于用户。

## 3. 社区热议与争议点
- **反 AI 政策**：支持者认为可为社区做"净化"、过滤 AI slop；反对者指出规则反而促使人们隐藏 AI 痕迹，甚至可能沦为 AI 公司的优质训练数据来源。
- **"贡献"定义之争**：有人反驳原文，强调"报告 bug 本身就是贡献"，不该贬低用户参与。
- **博客自身的双标**：多位评论者指出，文章一边批评 Codeberg 表态，一边用脚本在切换标签页时篡改标题/图标（如"Rick Astley""waifu pillow"）来惩罚开启 JS 的访客，颇具讽刺；该 JS 后被悄悄改名 `/js/kill..js`。
- **反 JavaScript 情结**：引出 NoScript 老用户对 Cloudflare、Anubis 等日益敌意化 Web 的怀旧与吐槽。

## 4. 行业影响与未来展望
事件折射出去中心化 Git forge 在 AI 时代的治理困境：平台越是坚持价值观，越可能与用户自由产生摩擦。如何在反 AI 滥用、维护社区质量与保持中立包容间取得平衡，将是 Codeberg 等 FOSS 替代方案的长期课题。
