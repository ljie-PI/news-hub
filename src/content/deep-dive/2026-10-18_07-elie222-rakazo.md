# elie222/rakazo

## 定位与痛点剖析

Rakazo 是面向个人与团队的持久化智能体平台，把模型、记忆、任务、语音和“电脑”统一进网页、桌面与移动端聊天界面。它针对自托管助手在线、跨会话执行及凭据归属。GitHub REST 显示默认分支为 main、Apache-2.0 许可；批次快照为 4461 星、800 个派生、本周增加 784 星，与查询时一致。项目仍标为测试版。

## 核心架构与技术细节

默认分支是 pnpm 与 Turborepo 管理的 TypeScript 单仓：apps 拆出 Hono／oRPC 接口、Graphile Worker、React 网页、Electron 桌面和 Expo 移动端，PostgreSQL／Prisma 持久化。Pi 智能体运行在接口或工作进程，电脑侧由 SandboxProvider 抽象 Docker、E2B、Daytona、CreateOS、Box；模型通过浏览器、终端和文件工具操作隔离环境。团队电脑共享工作区但各机器人保有独立显示与浏览器档案，文档明确这些目录不是安全边界。自托管还需长期接口、工作进程、数据库和沙箱，并非静态应用。

## 竞品对比与生态站位

OpenClaw 的官方 README 以单一 Gateway 连接控制界面、命令行及二十多种消息渠道，主会话工具默认在宿主机执行，沙箱需另配。Rakazo 更强调开箱即用的聊天产品、多端客户端与默认电脑供应商抽象；代价是部署组件更多、资源与运维负担更重。前者以 MIT 许可和插件生态见长，后者以 Apache-2.0 单仓整合产品层，两者都支持自选模型。

## 开发者反馈与局限性

开放 issue #1404 仅代表用户报告：配置 Greylog MCP 时反复索要凭据且未完成任务；#1387 报告 Docker 沙箱浏览器重启并丢失标签页状态，目前仍开放。另一方面，#1454 的回复段落拼接和 #1455 的侧栏时间错误，分别由合并 PR #1461、#1463 在当天修复，显示维护响应快；近期 PR #1462 仍在推进事件触发例程。主要风险是测试版行为、电脑资源开销、共享团队工作区的隔离边界，以及升级流程仍有开放提问。
