## 核心观点 / 产品机制

源码显示核心并非全局网络网关：Claude Code 的 PostToolUse 在模型读取成功工具结果前本地扫描并用占位符改写；WebFetch、WebSearch 出站参数可改写，未知或 MCP 参数默认拒绝。Codex 仅报告或阻断输入，Copilot 可替换模型侧提示，二者都不看工具流；VS Code 不做遮蔽。可选 shim watch 仅代理 Claude 流量，正文不落盘，从提供方 usage 统计词元，并按内置价格表估算 API 成本；订阅场景不是账单。记录默认只存临时的类别、计数和脱敏目标，无产品遥测，长期 ledger 须主动开启。PyPI 包 shim 当前1.2.2，制品哈希与注册表一致；官网仍写1.2.1，存在文案滞后。

## 社区热议与争议点

GraphQL 以10×5取回10个顶层、9个回复，所有连接均无下一页，但少于 commentsCount=20，故仅称19节点可见子图；用户身份被接口脱敏。独立评论给出四个具体争点：有人认可“本地、无遥测”；有人追问约70毫秒启动开销；有人问脚本打印环境文件后再外传；还有人担心占位符被写回配置会破坏文件。Maker 口径分别称检查发生在本地钩子、代理仅供观察；成功命令输出可遮蔽，但失败输出和脚本自身网络外传不可拦；占位符也不会还原，确会造成坏配置。支持点是透明且可审计，反方边界则接近“降低暴露”而非沙箱或数据防泄漏边界。

## 行业影响与未来展望
