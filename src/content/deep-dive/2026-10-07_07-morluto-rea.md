# morluto/rea

## 定位与痛点剖析
REA 是面向编码智能体的本地逆向工程层：把原生二进制、JavaScript／Electron、.NET、网页、安卓包与固件分析统一成命令行和 MCP 接口。它针对的不是“再造一个反编译器”，而是减少开发者在多个工具间搬运符号、调用图与运行证据的成本，并要求结论携带证据、未知项和限制。批次快照为单日新增 2963 星、累计 9111 星及 1002 次复刻；当前 GitHub API 查询为 9152 星、1004 次复刻，二者口径分开。

## 核心架构与技术细节
默认分支为 `main`。当前代码清单显示主体是 TypeScript，按 `src/domain`、`src/application`、`src/server` 分层，并为 Hopper、Ghidra、IDA、浏览器、进程、安卓和固件设置适配目录。命令行与 MCP 共用应用工作流和 Evidence 合约；目标绑定的会话路由经确定性注册表选取深度分析提供方，不在失败时静默切换。公开包 `rea-agents` 为 4.1.0，要求 Node.js 22.19 以上的指定版本线。README 自报各工具族数量；这些是项目口径，并非独立评测。

## 竞品对比与生态站位
Ghidra 官方定位是覆盖多平台、处理器和文件格式的完整逆向框架，兼具交互、自动化、反编译与脚本能力；REA 更像其上层编排与证据协议，还能接 Hopper、IDA 及跨网页／应用工作流。更近的 Ghidra Headless MCP 专注无界面 Ghidra，README 自报 212 个工具并支持事务式修改和脚本。REA 的优势是多提供方与跨层调查，代价是边界更复杂，深度原生分析仍依赖外置工具。

## 开发者反馈与局限性
README 明确不保证恢复原始源码；进程捕获以用户权限运行，不是安全沙箱，Windows 原生支持也仍是受限范围。开放 issue #793 报告 Fedora 上安装程序接受固定的 Hopper 6.4.2 RPM 后，又因启动器散列不匹配而拒绝配置，意味着推荐安装链在该环境可能不可用；该报告目前无维护者回复，不能写成已确认根因。项目虽更新频繁，但 102 个开放 issue／PR 也提示快速扩张带来的兼容面。
