# github/gh-stack

## 定位与痛点剖析

`gh-stack` 是 GitHub 官方推出的 `gh` CLI 扩展，主打 Stacked PRs（堆叠式拉取请求）。传统开发中一个大改动往往塞进单个巨型 PR，导致评审困难、反馈缓慢。堆叠式做法把大改动拆成一串小而可评审、层层依赖的分支与 PR。痛点在于手动维护这种链条极其繁琐：建分支、逐层 rebase、设置正确的 base 分支、在各层间跳转，`gh stack` 将这些自动化。目前该功能处于私有预览（private preview），需在 gh.io/stacksbeta 排队开通。

## 核心架构与技术细节

项目 100% 由 Go 编写，作为 `gh` 扩展分发，要求 `gh` v2.0+。栈元数据存于本地 `.git/gh-stack`（JSON，不入库），中断的 rebase 状态另存于 `.git/gh-stack-rebase-state`。核心命令包括 `init`、`add`、`checkout`、`rebase`、`submit` 等；`rebase` 支持级联 rebase，PR 合并后自动切换 `--onto` 模式，并自动启用 `git rerere` 记忆冲突解决。导航模型用 up/down/top/bottom 表达远离或靠近 trunk。还提供 8 种退出码与终端主题自适应。

## 竞品对比与生态站位

对标 Graphite、`git-branchless`、Sapling 等第三方堆叠工具。`gh-stack` 最大优势是官方原生：PR 在 GitHub 界面上以 Stack 形式互相链接，各层 base 自动指向下层分支，评审者只看该层 diff。它还提供 `gh skill install` 让 AI 编码代理理解堆叠工作流，紧扣 GitHub 的 AI Agent 生态叙事。

## 开发者反馈与局限性

仓库获约 537 star、24 fork、77 commits（自报口径），已发布至 v0.0.8。最大局限是强依赖尚未 GA 的服务端预览功能——未开通则完全不可用，MIT 许可但生态封闭度高。版本号偏早期，稳定性待验证。
