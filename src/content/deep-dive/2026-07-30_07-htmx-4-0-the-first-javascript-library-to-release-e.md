# Htmx 4.0：史上第一个"独占登陆 Game Boy"的 JavaScript 库

## 事件背景

htmx 作者 recursivedoubts 以一贯的恶搞风格宣布：htmx 4.0 将"独家在 Game Boy 与 Game Boy Color 上发布"。这不是比喻——它真的是一款受《超级马里奥》启发、正儿八经的 Game Boy 游戏，横跨三个生态区、四个关卡，终点是一座"糟粕工厂"，玩家要在此迎战最终 Boss"Warren Buffering"（作者调侃是自己在网上"结仇但其实是朋友"的角色）。只有击败他，才能解锁 htmx 4.0 的源代码。游戏在 swag.htmx.org 商店页面上架销售。

## 核心观点 / 产品机制

这个营销噱头精准命中了 htmx 的社区文化：技术扎实、保持极简、适用面广，却从不把自己太当回事。把"解锁源码"包装成通关奖励，既是玩笑，也隐晦地宣告 v4 正式版临近。评论中透露 v4 已进入 beta，源码里带有一些"skills 文件"，显示其正拥抱 AI 辅助开发的工作流。

## 社区热议与争议点

讨论迅速从玩笑发散到"前端该不该这么重"的路线之争。rpdillon 盛赞 htmx"从 intercooler.js 时代就爱不释手"，vibe 极佳。antihero 承认自己"抵制多年"，但被 React 折腾到厌倦后让 Claude 用 htmx 写了个小项目，觉得很不错——不过他也吐槽 htmx 的痛点："服务端怎么做类型安全的模板？"yawaramin 回应可用标签模板字面量解决。反方与替代派也很活跃：Incipient、oliwary 等一群人力挺 Vue + Quasar，认为 React 对多数项目"过度工程"，Quasar"开箱即用的东西多到离谱"；bel8、no_wizard 则批评 Quasar 把样式与组件耦合太死，覆写麻烦。trueno 情绪最激烈："基于 React 的那套彻底跑偏了，Web 应用逻辑塞进前端简直荒谬，前端就该只是前端。"

## 行业影响与未来展望

这场"Game Boy 发布会"是 htmx 品牌力的又一次胜利：用幽默强化"回归服务端、拒绝前端臃肿"的技术主张。随着 v4 beta 附带 AI skills 文件、社区自发总结"如何让 Claude 写 htmx 模板"的规范，htmx 正把自己定位成 AI 辅助编码时代"轻前端"路线的代表，与 React 阵营的分野只会愈发清晰。
