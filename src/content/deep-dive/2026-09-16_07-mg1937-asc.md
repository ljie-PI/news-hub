# MG1937/ASC

## 定位与痛点剖析

ASC 是面向移动安全研究者与自动化代理的 Android 按需反编译前端，重点不是一次性展开整包，而是快速查找类，或检索字符串、类型、方法、字段引用后再取目标代码。它适合数百兆、多 DEX 应用中“先定位、后阅读”的任务。批次快照为 1137 星、194 个分叉，本日新增 122 星；这些仅反映上榜热度。

## 核心架构与技术细节

项目以 Python 3.10+ 编写，依赖 Androguard 4.1.3。主链路用内存映射读取 APK 中央目录，并行处理 DEX；随后懒解析各类标识表，以字节正则、转换表和整数位图预筛指令引用，再把偏移常数时间映射回方法。命中类后，重映射索引、依赖、注解与字节码，内存重建最小 DEX，交给经裁剪的 Androguard DAD 输出源码。README 自报在 352MB 商业 APK 上全局引用搜索 1.79 秒、单类反编译 177 毫秒、内存 141MB，未见独立复测。

## 竞品对比与生态站位

JADX 提供资源解码、去混淆、调试与完整图形界面，能力更全但全局处理更重；Garlic 用 C 覆盖整包、DEX、JAR 及 ELF；DexKit 则以 C++ 和丰富条件查询擅长运行时定位混淆对象。ASC 的差异是把轻量查询、最小 DEX 重建和可读源码串成 Python 命令行流程，利于代理接入，但不能据现有材料断言速度全面领先上述工具。

## 开发者反馈与局限性

当前 main 对压缩 DEX 仍调用 zlib 完整解压；维护者在 issue #4 明确称 README 所述跳块解压只是实验功能，尚未合入。issue #20 暴露 Python 3.10 正则兼容故障，已由合并的 PR #24 修复；但 PR #13 所述无序字符串数据导致漏报或误报仍未合并。供代理消费的结构化 JSON 输出也停留在开放 PR #15，现行接口以文本为主。项目版本仅为 0.1.0，且尚无 GitHub Release，成熟度与宣称性能仍需真实 APK 复核。
