# AtomicBot-ai/atomic-agent

## 定位与痛点剖析

Atomic Agent 是 MIT 许可的本地优先通用代理：控制循环、会话、记忆和密钥留在本机，可驱动浏览器、文件与获批命令，也可接云模型。它瞄准小型量化模型在长任务中格式易坏、上下文膨胀和反复编码的痛点。批次冻结为 3004 星、255 次复刻、周增 547 星；本次 REST 查询仍为 3004 星、255 次复刻，前者仅代表选中快照，周增不能由当前 API 替换。

## 核心架构与技术细节

默认分支为 main，公开版本 0.6.7；主体是要求 Node.js 25.7 以上的 TypeScript。AgentLoop 每步组装稳定前缀与受预算约束的可变尾部，本地 llama-server 以 GBNF 约束一次输出工具调用数组，调度器并行执行独立读取，写操作穿过审批屏障，结果再压缩回会话。SQLite 与全文索引承载会话和记忆；Playwright 提供紧凑可访问性树；CLI、HTTP 服务及 Tauri 的标准输入输出协议共用运行时。Fusion 模式再由编排模型把独立工作扇出给临时执行者。

## 竞品对比与生态站位

Cline 官方仓库已覆盖编辑器、终端、桌面和开发套件，编码审阅体验更成熟；Hermes 则突出多消息渠道、七类终端后端及可自增长技能。Atomic Agent 的站位更窄而更底层：紧贴 llama.cpp、缓存槽复用、语法约束和可嵌入侧车，适合消费级硬件上的本地操作代理。其“同模型下 GAIA 一级准确率 69.8%，Hermes 为 58.5%”属于项目自报实验，不等同独立基准。

## 开发者反馈与局限性

开放 issue #602 报告 0.6.6 在 Windows 因缺少原生建目录、移动工具并默认经 cmd.exe 执行而陷入循环；当前主分支仍无这两个结构化工具，虽合并的 #618 已加入自动上下文压缩。issue #600 获协作者确认：较旧 llama.cpp 会拒绝默认的超长推理语法；修复 PR #601 尚未合并，可暂把推理预算设为零或不高于 499。项目仍标注开发者预览，接口会变，且暂不支持英特尔处理器的苹果电脑。
