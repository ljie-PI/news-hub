# paperclipai/paperclip

## 定位与痛点剖析

Paperclip 是管理多代理工作的开源控制平面，而非新的模型或代理框架。它面向同时运行 Claude Code、Codex、OpenClaw 等工具的个人与团队，把散落的终端、脚本和定时任务收束为公司、目标、项目、工单与汇报关系，重点解决任务重复领取、上下文丢失、预算失控以及人工无法持续监督的问题。

## 核心架构与技术细节

系统由 Node.js 服务端与 React 界面组成，开发环境可自动启动嵌入式 PostgreSQL，生产环境可外接数据库。代理通过心跳被唤醒，数据库队列负责合并触发、预算检查、工作区解析、密钥与技能注入；原子签出和执行锁避免重复工作。控制面还覆盖组织图、审批、成本事件、定时例程、插件、审计日志及多公司隔离，并通过适配器连接本地命令行或 HTTP 代理。

## 竞品对比与生态站位

它与 Asana、Trello、Linear 的任务外观相似，但原生建模代理身份、心跳、运行状态和成本；与 LangGraph、CrewAI 等执行框架相比，它不规定代理内部推理，而负责组织治理。其“自带代理”策略兼容面更宽，不过单代理用户收益有限，且现阶段不能替代代码评审，也尚未完成外部工单系统接入。

## 开发者反馈与局限性

近期 issue #11188 报告创建工单时缺少项目与目标归属校验，可能让任务无法进入隔离工作树；PR #10556 则修复热重启期间嵌入式数据库与活跃任务的生命周期问题。另一项 PR 显示公司导入曾丢失任务时间戳和父子层级。README 还明确匿名遥测默认开启，虽称不采集提示词、路径或密钥，敏感部署仍应主动审查并关闭。大量并行改动也意味着升级前需验证迁移和兼容性。
