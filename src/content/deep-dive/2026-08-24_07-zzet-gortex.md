# zzet/gortex

## 定位与痛点剖析

Gortex 是面向 AI 编程代理与 IDE 的本地代码智能引擎，本周榜单冻结新增 318 星。它试图替代代理反复读整文件、逐仓搜索的做法：预先把符号、调用链、接口契约与影响范围组织成图，再通过 CLI、MCP 和 HTTP API 按需返回上下文。目标用户是维护大型、多语言或跨服务代码库的开发者；当前仓库为 Apache-2.0，主语言为 Go。

## 核心架构与技术细节

`go.mod` 指定 Go 1.26.6，依赖 Cobra、tree-sitter、fsnotify 与 SQLite。官方架构文档显示，多仓索引器并发解析文件，解析器生成节点和边，类型感知解析器连接跨文件、跨仓引用；长驻守护进程把图持久化到同一 SQLite 库，文件变化触发增量修补。CLI、MCP 与 HTTP 共用查询引擎，并按仓库、项目或工作区限定范围。所谓支持 257 种语言、单次响应最多节省 50 倍 token，均是 README 自报口径，并非独立复测结论。

## 竞品对比与生态站位

Serena 官方 README 采用 LSP 或付费 JetBrains 后端，强项是符号级检索、编辑和重构；GitNexus 则以 tree-sitter、LadybugDB 构建本地图谱，并提供浏览器图形界面。Gortex 的差异点是单个 Go 二进制、共享持久图和跨仓契约分析，且许可证更宽松；但 GitNexus 的可视化入口、Serena 借成熟语言服务器获得的语义能力，各有更清晰的使用优势。

## 开发者反馈与局限性

开放 issue #651 报告一次自索引时接收器重绑定停滞两小时；维护者确认日志中的停滞有效，但未复现同等环境，只把查询计划列为首要假设，因此不能视为已确认通用缺陷。issue #648 反馈 `.hxx` 未进入 C++ 解析器，已关闭，修复 PR #653 已合并；维护者说明要到下一版本提供，最新 v0.63.8 发布早于该合并。近期 PR #650 仍开放且经历两轮要求修改，也说明复杂查询在联邦、截断和覆盖层语义上仍在收敛。
