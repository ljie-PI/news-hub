# A new Go API for JSON

## 事件背景

2026年11月4日，Go团队宣布`encoding/json/v2`与`encoding/json/jsontext`随Go 1.27稳定发布。兼容承诺使旧接口难以直接修正宽松解析、选项传递及伪流式问题，团队遂历时约六年另建命名空间。批次冻结热度为180 points、77 comments；本轮刷新Algolia实取75个可见节点，未触及100条上限，两种口径不混用。

## 核心观点 / 产品机制

新架构把语法处理交给`jsontext`，以状态机读写值或令牌；`json/v2`负责Go类型与JSON语义映射。它默认拒绝无效UTF-8和重复键，字段名区分大小写，空切片及映射输出空数组或对象。所有入口均可接收选项，新接口直面读写器，并让自定义类型通过编解码器流式处理。Go团队引用的基准显示具体类型序列化相对旧版介于快1.4倍至慢1.2倍；官方博客称反序列化最高可达10倍，均属项目方基准，并非本轮独立复测。

## 社区热议与争议点

评论中，txomon称公司曾用`jsontext`为复杂客户端提供细分错误，体验良好，但仅属单一案例。Philip-J-Fry认为多数服务的旧版已够用，网络读写后纳秒级收益往往不重要。SkiFire13担心空切片默认编码为空数组会成为新坑；travisd承认会影响部分用户，但认为这更符合常见接口模式。争论说明价值不仅在速度，也在默认语义是否值得迁移成本。

## 行业影响与未来展望

双版本互操作让库作者先采用流式接口，应用按调用点切换；旧版仍长期保留。严格默认值可能提升跨语言一致性与输入安全，但存量系统须回归`null`与空集合、重复键、字段大小写及自定义方法。迁移指南建议用兼容选项逐项放开，生产环境还可影子比较两版输出。
