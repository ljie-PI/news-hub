# AgentScore

## 事件背景
AgentScore 于 9 月 23 日作为 Latitude 第九次发布登上 Product Hunt；本批冻结数据为 147 票、6 条评论、当日第 5。厂商称其回答“生产 Agent 是否持续变好”，把结果、可靠性、成本、速度、安全合成每日分数。可核验的是对应页面、文档和 MIT 开源实现均已上线；尚无独立客户效果或准确率验证。

## 核心观点 / 产品机制
接入 OpenTelemetry 或既有生产轨迹后，系统从最短可用的 7、14、21、28 日窗口计算 0—100 分，并展示五个子分、证据与 95% 置信区间；五维权重在当前源码固定为 35%、25%、15%、15%、10%，任一维证据不足即不发布总分。当前文档与源码门槛为至少 50 个合格会话，但官网仍写 1000，属公开口径漂移。源码还核实每日快照、整会话重采样 400 次及版本化校准；这些证明实现存在，不证明评分有效。

## 社区热议与争议点
官方 API 按发布 ID 核得全部 6 条顶层评论及 1 条回复，无下一页，但账号均被脱敏。具体反馈有四类：一条仅称赞“开源万岁”；一条担心单一总分掩盖“更快更便宜但稍不可靠”的交换，并询问子分，文档确认子分可见；另一条要求自定义权重、让安全高于速度，而源码显示目前为固定权重；还有一条问能否发现传统日志遗漏的问题，产品方只简答“有 flaggers”。样本以祝贺和提问为主，不能视作真实部署评价。

## 行业影响与未来展望
它把分散的可观测指标压成可追溯、带不确定性的健康指标，便于回看失败会话并生成评测；风险是加权总分诱发“为分数优化”。公开 issue #4674 指出 Outcome 判定不读取工具返回，静默错误可能漏检；源码注释证实该输入边界，但 issue 结论仍待维护者处理。若要成为跨 Agent 基准，需稳定门槛版本、公开校准与外部复现，并让业务自行表达权重。
