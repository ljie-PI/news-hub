# dif.sh

## 事件背景

dif.sh 于九月五日登陆 Product Hunt；本批冻结为第一名、三百二十九票和三十八条评论，官方接口按编号核对无误。Maker 称起因是 Claude Code 配置传统开关时被注册与密钥流程卡住，最终退回环境变量，于是团队把实验配置改造成代理可直接操作的仓库文件。

## 核心观点

每个开关或实验是一份带结构化前置信息的 Markdown，记录负责人、假设、受众、变体权重、指标与决策。`dif validate` 检查字段、权重和实验冲突；`dif build` 生成类型化客户端及 `dif/context.json`，让代理读取活跃实验和历史结论。分桶在本地确定执行，事件可送自有分析系统或 Dif Cloud；云端给出提升幅度与置信区间，但变更仍以拉取请求回写。公开仓库采用 MIT 许可。

## 社区热议

评论形成三组具体观点。独立用户 fmerian 认为多家同类服务收缩使开源方案正逢其时，Maker 强调 Git 才是事实源。Amy Bradley 担心仓库扩大后文件失控；产品方称文件很小，可凭上下文与页面日志清理旧实验，但这仍是自述。另一位独立用户直指 Git 开关需要提交、评审和部署，无法充当凌晨事故的即时熔断器，还可能遗留死开关；产品方承认没有远程熔断是取舍，仅称命令行与代理有助发现陈旧项。官方接口取得二十条顶层评论和十九条回复，身份字段被脱敏；昵称只采用静态页可交叉者。

## 行业影响

它把实验治理从外部控制台拉回代码评审，契合代理以文本上下文工作的趋势，也降低供应商停服后的迁移风险。不过本地可审计与即时运维控制存在张力；官方文档还说明当前事件逐条发送，不批处理、不重试、离线不缓存，网络失败会丢失。因而它更像代理友好的实验即代码底座，而非成熟远程开关平台的无条件替代品。
