# e2b-dev/infra

## 定位与痛点剖析
e2b-dev/infra 是 E2B 开源的底层基础设施仓库，为 E2B 云平台提供支撑。E2B 定位于 AI 代码解释（code interpreting）的开源基础设施，让开发者能为 AI Agent 定制、管理运行环境并在云端安全执行代码。AI Agent 运行不受信任的生成代码时，面临沙箱隔离、快速冷启动、环境可复现与可自托管等痛点。该仓库把驱动 E2B 平台的这套基础设施开源，解决企业既想用 Agent 沙箱、又需数据自主可控的矛盾。

## 核心架构与技术细节
项目以 Go 语言为主，基础设施通过 Terraform 部署，强调基础设施即代码的可复现交付。它构成 E2B 沙箱运行时的底座，与主仓库 e2b-dev/E2B 提供的 SDK 和 CLI 配套：后者面向开发者定制与管理环境，本仓库则负责底层的沙箱调度与云端运行能力。在云支持上，GCP 已完整支持，AWS 处于 Beta 阶段，Azure 与通用 Linux 机器尚在规划中。仓库提供自托管指南与 CONTRIBUTING 文档，便于社区在自有云上完整搭建这套基础设施。

## 竞品对比与生态站位
相较 Modal、Daytona 等 Agent 沙箱与云执行方案，e2b-dev/infra 的差异化在于完全开源且可自托管，把商业平台的底层能力直接交给用户。它在「AI 代码执行基础设施」这一细分赛道占据开源标杆位置，尤其契合对数据主权和合规有要求的团队。

## 开发者反馈与局限性
本仓库 star 数约一千三，热度低于面向开发者的主仓库，属偏底层项目。局限在于自托管门槛较高，依赖 Terraform 与云平台运维经验；且目前仅 GCP 完整支持、AWS 仍为 Beta，多云覆盖尚不完善。
