# FetchSandbox MCP

## 事件背景

FetchSandbox MCP 针对代理会写集成、却难证明工作流正确的问题，本批获二百零一票、三十一条评论、三项评测、评分四点三三，日榜第二。“七十多个沙箱”为官方自报，官网各页另见四十多个、六十八个、七十五个，口径随版本漂移。

## 核心观点 / 产品机制

本地进程连接 Cursor、Claude Code 等，再经加密请求访问云端；三个工具可导入网址或粘贴的开放接口规范、列出并运行流程。引擎生成有状态且按模式校验的响应，能重放重复、乱序、陈旧事件，注入指定错误码、延迟与限流，并以终态、必需事件和不变量生成公开收据。产品方称约十五种接口有精选故障库，其余多为通用流程，故“覆盖”不等于都能复现真实故障。无需注册或密钥，但收据只是厂商证明而非独立凭据。

## 社区热议与争议点

官方接口按冻结编号取得十一条顶层评论、十六条回复；首帖回复仍有下一页且身份隐去，只能确认二十七节点子图。普通用户认可重复扣费、乱序回调的终态检查，也追问是否验证实际值而非形状。另有用户建议收据加入逐步差异，疑似产品方承认细微字段漂移易漏、尚在路线图；还有用户问能否从错误遗留状态播种，未见答复。自称联合创始人的首帖及面向产品内部机制的回复均只作产品方口径。

## 行业影响与未来展望

它把契约测试推进为代理工作流预检，但仍不能替代供应商沙箱。隐私边界：粘贴规范会发往云端，匿名遥测默认开启；官方称不记录规范正文、请求体或凭据，沙箱按次隔离，企业版可自托管且无外连，但合规认证仍在推进。
