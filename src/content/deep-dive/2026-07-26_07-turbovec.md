# RyanCodrai/turbovec

## 1. 定位与痛点剖析
turbovec 是一个用 Rust 编写、带 Python 绑定的向量索引库，基于 Google Research 的 TurboQuant 量化算法构建。它瞄准的痛点是向量检索的内存与成本压力：一个 1000 万文档语料以 float32 存储需约 31 GB 内存，turbovec 号称能压进 4 GB，且检索比 FAISS 更快（自报口径）。对于隐私、内存或延迟敏感的本地 RAG 场景，它主打「纯本地、数据不出机器」，可与任意开源嵌入模型组成气隙式 RAG 栈。

## 2. 核心架构与技术细节
核心是 TurboQuant——一种数据无关（data-oblivious）的量化器，无需单独训练阶段即可达近最优失真率。工作流程为：先归一化剥离向量长度，再用统一随机正交矩阵旋转，使每个坐标服从可预测的 Beta 分布（高维下趋近高斯）；TQ+ 逐坐标校准两个标量修正有限维漂移；随后用 Lloyd-Max 标量量化把每维压成 2-bit（4 桶）或 4-bit（16 桶），位打包实现最高 16 倍压缩；最后用长度重归一化打分消除内积估计偏差。支持在线增量摄入（加即索引，无需重建）、O(1) 按 id 删除的 `IdMapIndex`、以及搜索时的 allowlist 过滤（在 SIMD kernel 内以 32 向量块粒度短路，选择性过滤几乎不付 SIMD 代价）。检索侧手写 NEON（ARM）与 AVX-512BW（x86）内核。

## 3. 竞品对比与生态站位
主要对标 FAISS。项目自报口径：ARM 上比 FAISS IndexPQFastScan 快 10–19%；x86 上 4-bit 配置领先、2-bit 略逊几个百分点；召回率在 OpenAI d=1536/d=3072 上比 FAISS 高 0.2–1.9 点。它还提供 LangChain、LlamaIndex、Haystack、Agno 的 drop-in 集成，站位为「本地优先的高压缩向量索引」。

## 4. 开发者反馈与局限性
项目 ⭐约 14270（自报口径），已发布至 PyPI 与 crates.io。局限性：低维场景（如 GloVe d=200）下 Beta 渐近假设较松，优势缩小甚至打平；x86 的 2-bit 配置逊于 FAISS 的 AVX-512 VBMI 路径；作为纯索引库不含托管服务，需自行搭配嵌入与存储。基准均为 10 万向量规模，超大规模表现有待社区验证。
