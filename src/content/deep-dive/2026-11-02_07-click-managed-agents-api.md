# Click

## 事件背景

Click 于 11 月 1 日以“可搭配任意模型的托管代理 API”上线。批次冻结为当日第 8 名、98 票、10 条评论；官方 GraphQL 以 post id 1287022 复核同值。它把模型循环、恢复、沙箱和浏览器封装成 HTTP 服务；“任意模型”尚无独立兼容性测试。

## 核心观点 / 产品机制

开发者创建含模型、指令与工具授权的不可变版本，再启动持久会话；结果经事件流、Webhook 或 API 读取。会话可配沙箱、浏览器、搜索及 MCP/HTTP 工具。Code Mode 让模型写短 JavaScript 串联工具，`searchTools` 提供按需发现入口；“支持数千工具”是营销主张，文档未给压力测试。权限按连接和会话授权，官方建议按用户配置短期凭据；Click 声称凭据静态加密、租户隔离，但用户鉴权、预算、审批与业务校验由接入方负责。隐私声明称输入输出可能为运维与改进保留“有限期间”，未给固定天数；连接器调用会把相关内容交给提供商。

## 社区热议与争议点

官方 API 取得 5 条顶层评论及 3 条回复，共 8 个可见节点，少于计数 10；身份均脱敏且无下一页。其一赞赏 Code Mode 与预装运行栈，并追问自带工具，产品方自述“适用于所有工具”。其二担心多商店 MCP 串权，产品方称每个代理只获明确授权，可按用户绑定连接。其三问定时代理卡在权限提示时能否区别于“忙碌”，未获答复。其四追问长会话失败后能否返回完整轨迹；回复只解释转向托管代理的动机。内部机制回复均属产品方口径，不是独立验证。

## 行业影响与未来展望

Click 代表代理基础设施从 SDK 走向托管运行时：团队可缩短上线时间，却把会话、凭据和工具结果交给新中间层。文档记录工具调用与失败状态，但中断中的外部动作会标为未知，仍需业务系统确认后再重试。审批、可观测性、明确保留期与多模型实测，将决定其能否越过原型阶段。
