# Floot MCP

## 事件背景

Floot MCP 于 9 月 24 日登上 Product Hunt，冻结为日榜第 2、289 票、61 条评论；官方 GraphQL 确认帖子 ID 为 1259609。它把原有一体化应用平台接入 Claude、ChatGPT 等客户端，目标是让用户留在对话里完成全栈应用交付。

## 核心观点 / 产品机制

Floot 不是再造模型，而是提供远程 MCP 工作区：客户端通过 Streamable HTTP 与 OAuth 2.1/PKCE 授权，模型以工具调用创建项目、改代码、跑 SQL、查日志、预览和发布。项目是可导出的 TypeScript/React 应用，平台托管 Postgres、登录、存储、邮件与部署。模型费用走用户已有订阅；Floot 按“构建动作”计量，成功的读写调用都算一次，免费层每日 100 次、滚动七日 400 次。移动构建、域名 DNS、下载代码和录入第三方密钥仍需回到网页。

## 社区热议与争议点

官方评论子图有 15 条顶层、43 条可见回复且已翻完，合计 58，与 commentsCount=61 相差 3 条，原因无法由 API 判定。Maker（产品方）称 Claude、ChatGPT 已足够会写软件，因此从自有代理转向 MCP；一位用户称数周内做出两款应用和新官网，另一位称相机租赁业务的客户与员工系统已运行一年；有人追问后端，产品方回复采用 AWS Lambda 与 Neon。样本几乎全是支持者自述或团队答复，不能当作独立性能验证。

## 行业影响与未来展望

这一路线把 AI 应用构建器从“自有代理加点数”改成“用户自带模型、平台出售执行与托管”，有望降低重复付费和部署门槛。真正考验仍是工具权限、动作额度、复杂项目可维护性，以及导出代码后能否脱离专有运行时；生产采用前应实测迁移、并发、故障恢复与账单。
